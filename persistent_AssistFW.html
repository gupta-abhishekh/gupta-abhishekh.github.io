Project Overview

Built and deployed an enterprise GenAI chatbot inside Microsoft Teams. Finance and business users ask questions in plain English and get answers from the data warehouse in seconds. The bot turns each question into SQL, runs it on Azure Synapse and returns a short, business-friendly summary with the supporting data. Users no longer need to write SQL or wait for a BI report.

The platform serves ~350 users across 6 business units. It handles ~1,200 queries per week, with role-based and row-level security on every request.

Key Features

  • Natural language to SQL: Converts plain-English questions into valid Synapse SQL across 45+ tables and views in 8 finance subject areas.
  • RAG-grounded answers: Retrieves schema details, KPI definitions and a finance glossary from a vector index. This keeps answers correct for domain terms such as "net revenue" or "YTD variance".
  • Native Teams experience: Adaptive Cards show summaries, data tables and follow-up suggestions. Users need no new tool or separate login.
  • Enterprise security: RBAC through Microsoft Entra ID groups, plus row-level security (RLS) in Synapse, so each user sees only their own data.
  • SQL safety guardrails: SELECT-only enforcement, allow-listed tables, row limits and query validation before execution.
  • Conversation memory: Keeps context across turns, so users can ask follow-ups such as "Now split that by region."
  • Automated delivery: CI/CD with GitHub Actions deploys to Azure Web App through dev, test and production environments.

Problem Statement

Finance and business users depended on analysts for most data questions. Simple requests, such as "What was Q2 spend by region?", went into a queue and took 1–3 days. Analysts spent a large part of their week on repeat ad-hoc queries instead of deep analysis. Self-service BI dashboards did not cover every question, and most business users could not write SQL. Any AI solution also had to meet strict rules on data access, so users could see only the data they were allowed to see.

Solution Approach

  1. Requirements & data mapping: Worked with finance stakeholders to collect the top 150 real business questions. Mapped them to Synapse tables, joins and KPI definitions.
  2. Knowledge layer (RAG): Indexed table schemas, column descriptions, KPI formulas, a business glossary and sample question-SQL pairs as embeddings. Retrieved only the relevant context for each question to keep prompts small and accurate.
  3. Text-to-SQL pipeline: Built a LangChain chain: classify intent → retrieve context → generate SQL → validate → execute → summarize. Used few-shot prompts and schema-aware instructions to cut wrong joins and invented columns.
  4. Validation & self-correction: Checked each query for syntax and safety before it ran. On an error, the bot sent the error back to the LLM for one automatic fix attempt.
  5. Security: Mapped Entra ID groups to bot roles (RBAC). Passed the user's identity to Synapse so RLS filters every result at the database level.
  6. Teams integration: Built the bot on the Bot Framework. Returned answers as Adaptive Cards with a summary, a data table and suggested follow-up questions.
  7. Deployment & operations: Hosted on Azure Web App. Automated build, test and deploy with GitHub Actions. Logged latency, token use, failures and user feedback in Application Insights.

Challenges

  • LLM hallucinations in SQL: The model sometimes invented columns or joins. Fixed with schema-aware RAG, few-shot examples and a validate-then-retry loop.
  • Business terms vs. column names: Users say "margin" while tables say gross_profit_pct. Solved with a glossary and KPI definitions in the retrieval index.
  • Data security: The bot must never show data a user cannot see. Passed user identity through to Synapse RLS, so security is enforced in the database, not only in the prompt.
  • Latency: Long prompts slowed answers. Cut context size by retrieving only relevant schema parts, which kept median response time near 8 seconds.
  • Token cost: Reduced cost with smaller prompts and caching of repeat questions, lowering token use by about 30%.
  • Ambiguous questions: Added clarifying follow-up prompts, for example "Do you mean fiscal or calendar year?", instead of guessing.

The Assist Framework sits between users and the data warehouse as a secure, conversational access layer inside the tool they already use every day: Microsoft Teams.
